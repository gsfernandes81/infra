## Where it stands

Built on the `ccr-87300a0c-3kalf9` branch of **both** repos, neither merged:

- **claude-sessions 0.5.0** — `agent`, `install`, `offload-all`, and the containers-first menu
  (its `docs/design.md` § *The hub*, mockups 1–15, and its own
  `docs/handoff/2026-10-26-hub.md`). Merging that branch **is** the release: the version bump
  rides it, and CI tags and publishes on the push to `main`.
- **infra** — `dev/compose.yaml` as project `dev` (hub, `cloudflared` sidecar, `infra-dev`,
  and `or3-dev`/`dd-dev`/`ds-dev` behind profiles), `dev/hub/`, base `2026.10.26` without
  claude-sessions or cloudflared, workspaces cloned into volumes, `.env` files in `~/.env.d`,
  and the plays for `-e container=dev`. Reasons: [`decisions.md`](../decisions.md), *The hub,
  as built*. What is left of the plan: [`plans/dev-pool.md`](../../plans/dev-pool.md).

Tested here, without the fleet: the hub round trip under a pty through a stand-in ssh (two
claude-sessions tests), `docker compose config` with the example `.env`, the plays'
syntax-check and their `.env` writes against stubs, and the Makefile's two new guards against
an old `.env` and an old project (each refused, then passed on the new one).

**Not verified anywhere, and the first things to look at on bring-up:**

1. **Claude Code reads hooks from a volume mounted over `/etc/claude-code/managed-settings.d`.**
   It should — it is a plain directory of plain files — but no box has shown it. Proof: a new
   claude in `infra-dev`, then the menu shows the session moving (busy → idle). If it never
   moves, the registry is not being written and this is why.
2. **The children's external volume names** (`or3-dev_or3-claude` and the rest) are guesses
   from each repo's old project name. Check with `sudo docker volume ls` before turning a
   child's profile on; a wrong name is refused by Compose, not silently created.
3. **Compose not demanding an inactive profile's external volumes.** compose-go drops
   resources no enabled service uses, so `make up` with only the hub and `infra-dev` should
   not ask for `or3-dev_*`. If it does, that is the error to expect.

## Bring-up, in order

Each block is for fish, pasted inside the shell it names.

**0. Release, then pin.** Merge claude-sessions' branch to `main` and wait for the `v0.5.0`
release. Put its two SHA-256s into `dev/hub/Dockerfile` (`CLAUDE_SESSIONS_SHA256_arm64`,
`_amd64`, now `FILL-FROM-THE-v0.5.0-RELEASE`, which the build refuses). Then merge infra's
branch to `main`; until step 3 the box keeps running the old `infra-dev`, and the base
`2026.10.26` publishes from that push.

**Push anything unpushed in `~/infra` on `zero` first.** From step 3 `infra-dev` works in a
fresh clone, and the host checkout stops being its `/workspace`; a commit left only there is
the 2026-10-25 divergence again (CLAUDE.md, *A host checkout that will not fast-forward*).

**1. The edge and host halves, from the control node:**

```fish
cd ~/infra/ansible
ansible-playbook playbooks/server-create-dev-container.yml -e container=dev --check --diff
ansible-playbook playbooks/server-create-dev-container.yml -e container=dev
ansible-playbook playbooks/server-create-dev-container.yml        # infra-dev: INFRA_SECRETS by line
```

It makes the `dev` tunnel, `dev.gsrpi.uk` and its Access application, then `~/.dev-secrets`
on `zero` with `authorized_keys` and `tunnel.json`, and writes `HUB_SECRETS` and
`HUB_TUNNEL_ID` into the existing `dev/.env`.

**2. Fill the rest of `dev/.env`** — the old one is infra-dev's alone, and `make up` names
every line it lacks. `ssh zero`, then:

```fish
cd ~/infra/dev
git pull --ff-only
for k in (grep -oE '^[A-Z][A-Z0-9_]*=' .env.example)
    grep -q "^$k" .env; or grep "^$k" .env.example >> .env
end
```

then edit the appended lines: `HUB_HOSTS=infra-dev`, `COMPOSE_PROFILES=tunnel`, and the
children's paths (they must exist as paths only when their profile is on, but must be *set*).

**3. Retire the old project and start the new one**, from a shell that is not inside
`infra-dev` (`ssh zero` arrives on the host's own tunnel, which this does not touch). Every
session in the old `infra-dev` ends here:

```fish
cd ~; and sudo docker compose -p infra-dev down   # from ~: in dev/ it would read the NEW compose file; NOT -v
cd ~/infra/dev; and make up
```

`make up` refuses, naming this command, if the old project's container is still there. It
builds the hub and the new `infra-dev` and starts the hub first; `infra-dev` clones the repo
into its volume on first start.

**4. On each client:**

```fish
cd ~/infra/ansible
ansible-playbook playbooks/client-home-ssh-config.yml -e container=dev
ssh dev
```

The menu opens on the containers, `infra-dev` among them. `make status` on `zero` shows the
hub, its tunnel and the offload passes.
