claude-sessions tests), `docker compose config` with the example `.env`, the plays'

**Not verified anywhere, and the first things to look at on bring-up:**

1. **Claude Code reads hooks from a volume mounted over `/etc/claude-code/managed-settings.d`.**
   It should — it is a plain directory of plain files — but no box has shown it. Proof: a new
   claude in `infra-dev`, then the menu shows the session moving (busy → idle). If it never
   moves, the registry is not being written and this is why.
2. **The children's external volume names** come from the 2026-10-25 fleet inventory, and the
   clone paths in `.env.example` (`~/or3`, `~/destiny-director`, `~/dossier`) are assumed.
   Steps 2 and 4 of the cutover check both; a wrong volume name is refused by Compose, not
   silently created.
3. **Compose not demanding an inactive profile's external volumes.** compose-go drops
   resources no enabled service uses, so `make up` with only the hub and `infra-dev` should
   not ask for `or3-dev_*`. If it does, that is the error to expect.

## The cutover — one, for all four containers (owner, 2026-10-27)

The steps, the proofs and the rollback are [`dev/README.md`](../../dev/README.md) § *The
cutover from the old layout*, and nowhere else, so they cannot disagree. In outline:

0. Merge claude-sessions (publishes `v0.5.0`), paste its `SHA256SUMS` into
   `dev/hub/Dockerfile` (the build refuses the placeholders), merge infra.
1. On zero: list what would not carry over from each of the four host clones — every
   workspace becomes a fresh clone in a volume, so unpushed work stays behind on the host.
2. On zero: pull, set the old `dev/.env` aside at 600 outside the directory, copy dd's and
   ds's `.dev-ssh/` into `~/.dd-dev-secrets` and `~/.ds-dev-secrets`, check volume names.
3. Control node: `server-create-dev-container.yml -e container=dev`, then the plain run.
4. On zero: check the paths the new `dev/.env` names.
5. On zero, from `~`: `docker compose -p <p> down` (no `-v`) for `infra-dev`, `or3-dev`,
   `destiny-director` and `dossier`, then `make dev` in `~/infra/dev`.
6. When dd-dev is first wanted: `docker cp` its `.env` into its env volume, restart it.
7. Control node: `-e container=or3-dev -e via_hub=true` — the phone's vessel tunnel is back.
8. Each client: `client-home-ssh-config.yml -e container=dev`, then `ssh dev`.

Down for a few minutes: every dev container (step 5) and the vessel tunnel (5 → 7). Running
claudes in `infra-dev` and `or3-dev` end; their conversations resume from Archived.
`dd-dev` and `ds-dev` stay stopped, as now, until `make up S=dd-dev`.
